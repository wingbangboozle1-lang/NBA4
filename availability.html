Availability & rotation

The official injury report states reported status and reasons; it does not state playing time. This page documents the reference engine's availability and rotation layer — the rotation-availability column the picks page must carry, and the top-8 minutes-share redistribution model — exactly as implemented, and shows what each part reports today: observed status with its official link, and model cells left blank. No availability probability, minutes estimate, production impact or game script is derived from an injury label here (rights gate G0; stances D-01/IR-T4 stand).

i
Keep the evidence chain separate.

A status report is an input observation. Availability probability, rotation minutes, player production and game-flow scenarios are modelled outputs that each need data, uncertainty and validation. The table below keeps them on separate rows for that reason — the injuries page publishes the observation side row by row, and the results page carries the per-player game logs behind the rotation estimates.

Top-8 minutes-share redistribution model

Minutes are a fixed budget: 240 team-minutes in regulation (five players × 48), plus five per overtime period. When one player's minutes fall, an equal amount must appear somewhere else — the model redistributes a constant, it never rescales one.

Refresh and snapshot controls

  • Keep each permitted official report version with source time and observed time.
  • Never overwrite a prior estimate after an injury update; create a new version.
  • Suppress picks if reports are late, stale, missing, or unresolved.
  • Do not use a previous day's report as a current slate status.
