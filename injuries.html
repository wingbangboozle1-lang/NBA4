Injuries, rotation & game flow

The official NBA injury report describes reported status and reasons, and the league says reports update continually. Below, every row of the 2026-11-16 10:00 AM ET report (72 rows: 8 games of 11/16 listed player by player or as NOT YET SUBMITTED, and 5 NOT YET SUBMITTED team rows for 11/17) is restated verbatim with the document and fetch time in the last cell. This repo has no licensed, timestamped injury history or tested rotation model, so it does not infer expected minutes, production or game script from an injury label — those cells stay blank.

i
Keep the evidence chain separate.

A status report is an input observation. Availability probability, rotation minutes, player production and game-flow scenarios are modeled outputs that each need data, uncertainty and validation.

Required analysis chain

Each step needs a timestamped source and its own validation.

1. Reported statusOfficial source observation; timestamp and version required.
2. AvailabilityProbability or unresolved state; do not treat status as certainty.
3. Rotation minutesConditional lineup and role distribution; currently blank.
4. ProductionConditional per-minute/possession distribution; currently blank.
5. Game flowScenario distribution and prop impact; currently not computed.

Refresh and snapshot controls

  • Keep each permitted official report version with source time and observed time.
  • Never overwrite a prior forecast after an injury update; create a new version.
  • Suppress picks if reports are late, stale, missing, or unresolved.
  • Do not use a previous day’s report as a current slate status.
