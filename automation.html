Automation & the three-day slate

The requested behaviour is a system that produces picks for every upcoming slate up to three days ahead, using this project's own originated lines, with no manual step. That machinery is implemented and unit-tested. It has never run on NBA data, because the rights gate refuses input that is not cleared — and that gate is the correct behaviour.

i
What "no manual input" means here.

Every step — ingest, rights check, freshness check, horizon filter, forecast, pick decision, ledger append — is executed by the pipeline. The only remaining human decisions are policy ones taken once, in advance: the data contract, the market specification, the validation thresholds and the stake policy.

Run it now

python3 scripts/run_pipeline.py \
    --inputs data/inbox-example \
    --out data/out-example \
    --now 2026-11-14T12:00:00Z \
    --run-id example-run

python3 -m unittest discover -s tests -t .

The example inputs are synthetic and deliberately carry allowed_use: false, so the run is suppressed by the rights gate and writes no pick. That is the intended demonstration.

Verified today

  • 90 engine unit tests pass (47 + 43) over synthetic fixtures.
  • The example run selects 2 events inside the horizon and then suppresses the run with RIGHTS_NOT_CLEARED.
  • The horizon constructor rejects a horizon longer than 72 hours.
  • Stale inputs and uncleared inputs both produce zero forecasts and zero picks.
  • A pick records its edge against a licensed quote; without a market specification it becomes no_bet.
  • A forecast below the declared minimum sample becomes no_bet (BELOW_MINIMUM_SAMPLE), and the ledger is append-only across runs.
