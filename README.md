# NBA4 — NBA line research dashboard

**Live site:** [https://wingbangboozle1-lang.github.io/NBA4/](https://wingbangboozle1-lang.github.io/NBA4/) (GitHub Pages publishes from `main` at the repository root; the deployment is re-checked after every merge.)

## Current status

This repository contains an evidence-first research plan **and a working reference engine** for it: data contracts with a hard rights gate, model-originated fair lines and prices, de-vigging, parlay/prop-combo joint probabilities, correlation estimators with game-cluster bootstrap intervals, validation metrics, a gate-aware leaderboard, and a three-day slate pipeline with an append-only ledger, plus refusal-by-default brief-gap modules (result-feed settlement, injury-revision diff, pre-registration gate, seal layer, pinned home-court, luck band, rest load, minutes share, market prior) that raise instead of inventing a value. The same requirement items also reach the repository as the parallel session's <code>engine/officialresults.py</code>, <code>engine/injurydiff.py</code>, <code>engine/preregistration.py</code>, <code>engine/publishedledger.py</code>, <code>engine/luck.py</code>, <code>engine/rest.py</code>, <code>engine/venues.py</code>, <code>engine/rotations.py</code>, <code>engine/markets.py</code>, <code>engine/totals.py</code>, <code>engine/surfaces.py</code>, <code>engine/confidence.py</code> and <code>engine/estimators.py</code>; both sets are kept, tested and cross-listed in <code>COORDINATION.md</code> (irregularity IR-T1) rather than one being deleted, because each is the record of a different session's reading of the brief and only <code>engine/seallayer.py</code> (the standings tie-break chain) has no counterpart on the other side. The engine ships with synthetic fixtures and 297 passing unit tests (47 + 43 + 17 + 10 + 132 + 48, six suites); it contains **no NBA or market data**, no trained model and no published pick.
The blocking issue is still data rights, not code. NBA's Stats FAQ states its statistics are "not available for download for either academic or personal use", and NBA.com's Terms of Use restrict NBA Statistics to "legitimate news reporting or private, non-commercial purposes" and state they "may not be used in connection with any gambling activity (including legal gambling activity)", nor with a "database ... of comprehensive, regularly updated statistics" without the Operator's express prior consent. The site now publishes **official observations only**: the 22 games inside the current three-day window (2026-11-15 11:29:57 UTC – 2026-11-18 11:29:57 UTC), restated from the official 2026–27 schedule PDF (rows 236–257, fetched 2026-11-15 11:39 UTC), and the 100 rows of the official 2026-11-15 06:15 AM ET injury report (revision 06:15 AM ET, retrieved 11:34 UTC), each with a link to the document and a fetch timestamp ([provenance files](data/snapshots/README.md), generated by [`scripts/build_snapshots.py`](scripts/build_snapshots.py)). No NBA statistics values, player or team data, odds, or model output are published, no pick is issued (every game carries a reason-coded NO PICK), and the engine still refuses any record whose permission flag is not set. Obtain written permission or a licensed contract, plus legal review of the product and rewards, before a betting model or public picks are considered.

## Local verification

```sh
python3 scripts/build_snapshots.py --check   # regenerate/verify the slate + injury tables from data/snapshots/
python3 scripts/check_site.py --with-tests   # page, link, table, snapshot and source-link checks + engine tests
python3 -m unittest discover -s tests -t .    # engine unit tests only
python3 scripts/run_pipeline.py \
    --inputs data/inbox-example \
    --out data/out-example \
    --now 2026-11-14T12:00:00Z                # synthetic smoke test
```

The checker verifies each page's title and single heading, that every page's tags nest correctly, every local link and fragment, every HTML table row's final source cell, every Markdown table row in `docs/` for an HTTPS source on an approved official-source domain, and that no page on disk is missing from the checked set. It does not fetch external sites; each cited source must be reviewed directly (the review log is in `docs/source-verification.md`). The site's own code uses static HTML/CSS only, with no third-party scripts or cookies and no form or data collection. GitHub Pages is different: GitHub states that "when a GitHub Pages site is visited, the visitor's IP address is logged and stored for security purposes" ([GitHub Docs, What is GitHub Pages?](https://docs.github.com/en/pages/getting-started-with-github-pages/what-is-github-pages)). This was flagged as T-03 on the Flagged for Review page.
